# Mini Git

커밋 그래프, 해시맵, 그래프 탐색, 직접 구현한 정렬 알고리즘과 역색인을 학습하기 위한 메모리 기반 Mini Git입니다. 파일 내용은 추적하지 않고 커밋 메타데이터와 브랜치 관계만 관리합니다.

## 실행 환경

- Python 3.10 이상
- 외부 라이브러리 없음
- 그래프 전용 라이브러리와 Python 표준 정렬 API를 사용하지 않음

프로젝트 루트에서 모듈로 실행합니다.

```bash
python3 -m mini_git
```

환경의 `python` 명령이 Python 3에 연결되어 있다면 다음 명령도 사용할 수 있습니다.

```bash
python -m mini_git
```

프로그램은 메모리에서만 동작하므로 종료하면 저장소 상태가 사라집니다.

## 명령어

명령어는 대소문자를 구분하지 않습니다. 공백이 들어가는 사용자명, 메시지, 검색어는 따옴표로 감쌉니다.

| 명령어 | 설명 |
| --- | --- |
| `INIT <user_name>` | 저장소를 초기화하고 `main` 브랜치와 작성자를 설정합니다. |
| `BRANCH` | 생성된 브랜치 목록을 출력하고 현재 브랜치에 `*`를 표시합니다. |
| `BRANCH <branch_name>` | 현재 HEAD를 가리키는 브랜치를 생성합니다. 첫 커밋 이후 사용할 수 있습니다. |
| `SWITCH <branch_name>` | 현재 브랜치를 변경합니다. |
| `COMMIT <message>` | 현재 HEAD를 부모로 하는 커밋을 생성합니다. |
| `LOG` | 부모가 자식보다 먼저 나오도록 커밋을 출력합니다. |
| `LOG --sort-by=date` | 커밋을 작성 시각 기준으로 출력합니다. |
| `LOG --sort-by=author` | 커밋을 작성자 기준으로 출력합니다. |
| `PATH <commit1> <commit2>` | 두 커밋 사이의 무방향 최단 경로를 출력합니다. |
| `ANCESTORS <commit_hash>` | 지정한 커밋의 모든 조상을 출력합니다. |
| `SEARCH <keyword>` | 메시지를 키워드 또는 공백을 포함한 구문으로 검색합니다. |
| `SEARCH --author=<name>` | 작성자로 커밋을 검색합니다. |
| `exit`, `quit` | REPL을 종료합니다. |

사용 예시는 [MANUAL.md](MANUAL.md)에 정리되어 있습니다.

## 핵심 자료구조

### 커밋 그래프

`CommitObject`는 다음 정보를 가집니다.

- `commit_hash`: 세션에서 유일한 커밋 식별자
- `message`: 커밋 메시지
- `author`: 작성자
- `timestamp`: 커밋 생성 시각
- `parents`: 부모 커밋 해시의 불변 튜플
- `branch`: 커밋을 생성한 브랜치

커밋은 부모 방향으로만 연결됩니다. 새 커밋은 이미 존재하는 현재 HEAD를 부모로 사용하므로 과거 커밋이 미래 커밋을 부모로 가리킬 수 없고, 그래프는 방향성 비순환 그래프인 DAG가 됩니다.

커밋은 `dict[hash, CommitObject]`에 저장해 전체 해시 조회는 평균 `O(1)`에 수행합니다. 해시 prefix 조회는 현재 커밋 해시를 확인하므로 `O(V)`입니다.

### 브랜치와 HEAD

브랜치 맵은 `branch_name -> commit_hash` 관계를 저장합니다. `current_branch`가 현재 HEAD 브랜치를 나타내며, 커밋이 생성되면 해당 브랜치의 해시만 새 커밋으로 이동합니다.

### 해시 생성

커밋 데이터와 증가 카운터를 SHA-256 입력으로 사용합니다. 카운터와 이미 발급한 해시 집합은 `INIT`을 다시 실행해도 초기화하지 않으므로 한 프로그램 세션에서 같은 해시가 다시 발급되지 않습니다.

### 역색인

커밋 생성 시 다음 인덱스를 갱신합니다.

- `keyword -> commit_hash 목록`
- `author -> commit_hash 목록`

메시지는 공백으로 나누고 소문자로 변환해 저장합니다. 단일 키워드는 해당 posting list만 조회합니다. 공백 검색어는 각 토큰의 posting list로 후보 교집합을 만든 후 후보 메시지만 확인하므로 모든 커밋을 순회하지 않습니다.

## 알고리즘

### 부모 우선 LOG

기본 `LOG`는 Kahn 방식의 위상 정렬을 사용합니다. 각 커밋의 진입 차수를 부모 수로 계산하고, 진입 차수가 0인 커밋부터 처리합니다. 따라서 모든 부모가 자식보다 먼저 출력됩니다.

- 시간복잡도: `O(V + E)`
- 공간복잡도: `O(V)`

### PATH

부모와 자식 연결을 무방향 간선으로 간주합니다. 목적지에서 BFS를 실행해 각 커밋에서 목적지까지의 최소 거리를 구한 뒤, 시작점에서 거리가 1씩 감소하는 이웃을 선택해 경로를 복원합니다.

최단 경로가 여러 개면 선택 가능한 이웃 중 해시가 사전순으로 가장 작은 커밋을 고릅니다. 같은 시작 prefix를 가진 경로에서는 처음으로 달라지는 해시가 전체 경로 문자열의 사전순을 결정하므로 요구된 동률 규칙을 만족합니다.

- 시간복잡도: `O(V + E)`
- 공간복잡도: `O(V)`

### ANCESTORS

부모 방향으로 BFS를 수행하고 방문 집합으로 중복을 제거합니다.

- 시간복잡도: `O(V + E)`
- 공간복잡도: `O(V)`

### 날짜와 작성자 정렬

`LOG --sort-by=date|author`는 직접 구현한 삽입 정렬을 사용합니다. `sorted()`와 `list.sort()`는 사용하지 않습니다.

- 최선 시간복잡도: `O(n)`
- 평균 및 최악 시간복잡도: `O(n^2)`
- 추가 공간복잡도: `O(1)`
- 안정성: 날짜 또는 작성자가 같으면 해시를 동률 기준으로 다시 비교하므로, 주 정렬 키만 기준으로 보면 기존 입력 순서를 보존하지 않는 비안정 정렬입니다.

## 프로젝트 구조

```text
mini_git/
  __main__.py    모듈 진입점
  repl.py        프롬프트와 반복 입력
  mini_git.py    명령 파싱과 출력 형식
  repository.py 저장소 상태와 알고리즘
  objects.py     커밋 데이터 모델
  errors.py      오류 종류별 메시지와 종료 코드
tests/
  test_repository.py
MANUAL.md
README.md
```

## 테스트

```bash
python3 -m unittest discover -s tests
```

테스트는 해시 유일성, 위상 정렬, 최단 경로와 사전순 동률 처리, 조상 탐색, 검색, 직접 정렬, CLI 입력 검증, REPL 오류 처리를 확인합니다.

## 구현 범위

- 파일 내용, Blob, 작업 트리 추적은 구현하지 않습니다.
- 네트워크 통신과 원격 저장소는 구현하지 않습니다.
- 파일 기반 데이터 영속성은 구현하지 않습니다.
- merge와 diff는 선택 과제이므로 포함하지 않습니다.
