# Mini Git에서 사용하는 자료구조

이 프로젝트는 해시맵에 저장된 커밋 객체를 부모와 자식 관계로 연결하여 커밋 그래프를 구성합니다. 그래프 탐색과 정렬, 검색을 위해 리스트, 튜플, 집합, 큐, 역색인 등의 자료구조도 사용합니다.

## 자료구조 요약

| 자료구조 | 사용 위치 | 역할 |
| --- | --- | --- |
| 해시맵 `dict` | 커밋 저장소 | 커밋 해시로 커밋 객체 조회 |
| 그래프 `DAG` | 커밋 관계 | 부모와 자식 커밋 연결 |
| 리스트 `list` | 출력, 인덱스, 자식 목록 | 여러 값을 순서대로 저장 |
| 튜플 `tuple` | 부모 커밋 목록 | 부모 관계를 변경할 수 없게 저장 |
| 집합 `set` | 방문 여부, 해시 중복 검사 | 중복 제거와 빠른 포함 여부 확인 |
| 큐 `deque` | BFS, 위상 정렬 | 먼저 들어온 커밋부터 탐색 |
| 역색인 | 키워드와 작성자 검색 | 전체 커밋 순회 없이 검색 후보 조회 |
| 디스패치 테이블 `dict` | 명령어 실행 | 명령어 문자열과 실행 메서드 연결 |

## 1. 해시맵

`repository.py`에서는 커밋을 파이썬 딕셔너리에 저장합니다.

```python
self.commits: dict[str, CommitObject] = {}
```

키는 커밋 해시이고 값은 커밋 객체입니다.

```text
커밋 해시 -> CommitObject
```

예시는 다음과 같습니다.

```python
{
    "a1b2c3...": CommitObject(...),
    "d4e5f6...": CommitObject(...),
}
```

전체 해시를 사용한 커밋 조회의 평균 시간복잡도는 `O(1)`입니다. 해시 prefix 검색은 저장된 커밋 해시를 순회하므로 `O(V)`입니다. 여기서 `V`는 커밋 수입니다.

## 2. 커밋 그래프

커밋 관계는 DAG로 구성됩니다. DAG는 방향성 비순환 그래프를 의미합니다.

부모 관계는 `CommitObject`에 저장합니다.

```python
parents: tuple[str, ...]
```

자식 관계는 별도의 해시맵에 저장합니다.

```python
self.children: dict[str, list[str]] = defaultdict(list)
```

구조는 다음과 같습니다.

```text
부모 커밋 해시 -> 자식 커밋 해시 목록
```

새 커밋은 이미 존재하는 현재 HEAD만 부모로 가리킵니다. 미래 커밋을 부모로 연결할 수 없기 때문에 순환이 만들어지지 않습니다.

부모와 자식 관계를 모두 저장하므로 다음 기능을 구현할 수 있습니다.

- `LOG`: 부모 우선 위상 정렬
- `PATH`: 부모와 자식 간선을 이용한 무방향 최단 경로 탐색
- `ANCESTORS`: 부모 방향 조상 탐색

## 3. 리스트

리스트는 여러 값을 순서대로 저장할 때 사용합니다.

대표적인 사용 위치는 다음과 같습니다.

- 명령어 인자 목록
- REPL 출력 문자열 목록
- 부모 커밋에 연결된 자식 커밋 목록
- 키워드와 작성자에 연결된 커밋 해시 목록
- 탐색 결과와 정렬 대상 커밋 목록

예를 들면 다음 구조는 한 부모 커밋의 자식들을 순서대로 저장합니다.

```python
self.children[parent_hash].append(commit_hash)
```

리스트 끝에 값을 추가하는 `append()`의 평균 시간복잡도는 `O(1)`입니다.

## 4. 튜플

커밋의 부모 목록은 튜플로 저장합니다.

```python
parents: tuple[str, ...]
```

일반 커밋은 부모가 없거나 한 개입니다.

```python
parents = ()
parents = (parent_hash,)
```

튜플은 생성 후 요소를 변경할 수 없습니다. 따라서 한 번 만들어진 커밋의 부모 관계가 실수로 수정되는 것을 막을 수 있습니다.

## 5. 집합

집합은 중복을 허용하지 않는 자료구조입니다.

이미 발급한 커밋 해시를 저장할 때 사용합니다.

```python
self._issued_hashes: set[str] = set()
```

그래프 탐색에서는 이미 방문한 커밋을 기록하는 데 사용합니다.

```python
visited: set[str] = set()
```

역색인 후보의 교집합을 확인할 때도 커밋 해시 목록을 집합으로 변환합니다.

집합에 값이 포함되어 있는지 확인하는 평균 시간복잡도는 `O(1)`입니다.

## 6. 큐

파이썬의 `collections.deque`를 큐로 사용합니다.

```python
ready = deque(...)
```

큐는 먼저 들어온 값을 먼저 꺼내는 FIFO 구조입니다. 다음 알고리즘에서 사용합니다.

- `LOG`의 Kahn 방식 위상 정렬
- `PATH`의 너비 우선 탐색
- `ANCESTORS`의 너비 우선 탐색

앞에서 값을 꺼내는 `popleft()`의 시간복잡도는 `O(1)`입니다. 일반 리스트의 첫 요소를 제거하면 이후 요소를 이동해야 하므로 `O(n)`이 걸릴 수 있습니다.

## 7. 브랜치 해시맵

브랜치 이름과 브랜치가 가리키는 최신 커밋 해시를 딕셔너리에 저장합니다.

```python
self.branches: dict[str, str | None] = {}
```

구조는 다음과 같습니다.

```text
브랜치 이름 -> 브랜치의 최신 커밋 해시
```

예시는 다음과 같습니다.

```python
{
    "main": "a1b2c3...",
    "feature": "d4e5f6...",
}
```

커밋이 없는 브랜치는 `None`을 가리킬 수 있습니다. `current_branch`에는 현재 선택된 브랜치 이름이 저장됩니다.

## 8. 역색인

검색을 위해 두 종류의 역색인을 사용합니다.

```python
self.keyword_index: dict[str, list[str]]
self.author_index: dict[str, list[str]]
```

구조는 다음과 같습니다.

```text
키워드 -> 커밋 해시 목록
작성자 -> 커밋 해시 목록
```

키워드 역색인의 예시는 다음과 같습니다.

```python
{
    "login": ["a1b2c3...", "d4e5f6..."]
}
```

`SEARCH login`을 실행하면 모든 커밋 메시지를 확인하지 않고 `login`에 연결된 커밋 후보만 가져옵니다. 작성자 검색도 같은 방식으로 동작합니다.

## 9. 디스패치 테이블

`mini_git.py`에서는 명령어 문자열과 실행 메서드를 딕셔너리로 연결합니다.

```python
self._command_handlers = {
    "init": self._init,
    "whoiam": self._whoiam,
    "branch": self._branch,
    "commit": self._commit,
    "search": self._search,
}
```

사용자가 명령어를 입력하면 딕셔너리에서 실행할 메서드를 찾습니다.

```python
handler = self._command_handlers.get(command)
```

명령어를 찾는 평균 시간복잡도는 `O(1)`입니다. 명령어별 `if` 문을 반복하지 않고 새로운 명령어와 메서드를 디스패치 테이블에 추가할 수 있습니다.

## 전체 구조

이 프로젝트의 핵심 구조는 다음과 같이 정리할 수 있습니다.

```text
명령어 디스패치 테이블
        |
        v
저장소 기능 실행
        |
        +-- 커밋 해시맵
        +-- 브랜치 해시맵
        +-- 부모/자식 커밋 DAG
        +-- 키워드 역색인
        +-- 작성자 역색인
        |
        v
큐와 집합을 이용한 그래프 탐색
```

현재 프로젝트에는 Heap이나 Blob 자료구조는 포함되어 있지 않습니다. 파일 내용이 아니라 커밋 메타데이터와 그래프 관계를 중심으로 구현되어 있습니다.
